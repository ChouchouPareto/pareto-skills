# 提炼用户需求

把模糊表达快速收敛为可理解、可执行、可核对的核心需求。追问服务于消除关键歧义，不把对话变成完整问卷。

## 工作流程

### 1. 提取已知信息

从用户原话中识别以下五类信息：

1. 目标：用户真正希望改变、解决或得到什么。
2. 对象与场景：给谁使用，发生在什么情境。
3. 交付物与范围：最终要产出什么，包含什么，不包含什么。
4. 硬性约束：时间、预算、渠道、格式、语气、技术、风险或禁区。
5. 验收标准：出现什么结果才算完成。

区分用户明确说出的事实、可以合理归纳的含义和仍待确认的假设。不得虚构信息，不得把推测写成用户决定。

### 2. 判断是否需要追问

如果现有信息已经足以形成可执行需求，跳过追问，直接总结。只有某个缺口会明显改变方案、交付物或成败标准时才追问。

优先追问目标，其次是交付物、对象与场景、硬性约束、验收标准。忽略不影响执行的偏好和背景细节。

### 3. 结构化追问

每轮最多提出三个问题，尽量让用户一次回复即可补齐。默认最多进行两轮；第二轮只问上轮答案引出的一个决定性问题。除非涉及安全、权限或不可逆操作，不因次要信息继续追问。

根据缺口选择下列形式：

- 选择题：存在少数互斥路径时，给出 2 至 4 个清楚选项，并允许用户自行补充。
- 填空题：需要具体内容时，给出可直接复制填写的短模板。
- 确认题：AI 已有高可信理解时，先复述判断，再让用户确认或修改。

问题应使用用户当前的语言和词汇。每个问题只解决一个决策，不询问已经提供的信息，不堆叠专业术语。

可按需使用以下填空结构，不要机械地全部展示：

```text
1. 最想解决的问题／达到的结果：____
2. 最终要得到的东西：____
3. 必须满足或绝对不能出现的条件：____
```

用户正等待快速结果时，先给出基于现有信息的暂定需求，再只问最关键的一项。

### 4. 收敛并总结

综合用户最初输入和后续回答，删除重复背景、过程性抱怨和不影响决策的细节。若信息冲突，以用户最新的明确回答为准；若无法判断，标记一个待确认点，不擅自替用户选择。

最终输出标题“核心需求”，正文最多五句话。优先覆盖以下内容，每一点不必各占一句：

1. 用户要实现的核心目标。
2. 使用对象和关键场景。
3. 所需交付物及范围。
4. 必须遵守的约束和优先级。
5. 验收标准，或唯一仍待确认的关键问题。

使用陈述句，保持具体、紧凑和可执行。不要附加长篇分析、思考过程、新建议或下一套问卷。若用户要求其他输出格式，可在不超过五句话的前提下适配。

## 输出示例

用户输入：“我想做一个给大学生用的兼职小程序，但不知道具体怎么说，预算也不多，希望先跑起来。”

追问：

```text
请补三项，直接填空即可：
1. 第一批用户主要在哪所学校或哪个城市：____
2. 首版最重要的动作（找兼职／发布兼职／报名与沟通／其他）：____
3. 可接受的上线时间和预算上限：____
```

信息补齐后的输出：

```text
核心需求
为指定校园的大学生和招聘方制作一款兼职信息小程序，首要目标是让学生快速找到并报名可信兼职。首版聚焦职位发布、筛选、报名和基础沟通，不扩展复杂社交或培训功能。项目须在约定预算内于指定日期前上线可测试版本，并优先保证信息真实性和操作简单。完成标准是第一批用户能够独立走通发布到报名的完整流程。
```
