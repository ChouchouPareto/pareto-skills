# PRD路线与模块选择

## 路线A：0→1产品设计

当项目是新产品或新业务线，需要从无到有定义整体形态时使用。

优先考虑：

- 产品定位、目标用户和核心价值；
- 市场、用户、竞品和现有解法；
- 产品架构和核心价值闭环；
- 账号、数据存储、权限等基础能力；
- MVP范围、功能优先级和版本路线；
- 完整用户旅程、系统交互和异常流程；
- 资源、排期、依赖、验收与核心指标。

不要因为想象了长期形态，就把所有功能都放进第一版。长期形态和MVP范围要分开。

## 路线B：现有产品的功能迭代

当产品已存在，需要新增、优化或替换某个功能时使用。

优先考虑：

- 当前问题及其数据或用户证据；
- 历史逻辑、现有用户与兼容约束；
- 功能入口、页面、跳转、状态和交互；
- 触发条件、业务规则、正常与异常分支；
- 角色权限、数据处理和与已有模块的关系；
- 埋点、灰度、兼容、回滚和验收。

小功能的文档可以很短，但必须说清执行逻辑。

## 路线C：AI/Agent产品或AI能力迭代

当产品依赖大模型、Prompt、RAG、Agent、工具调用或AI Workflow产生关键结果时使用。该路线可与A或B叠加，而不是互斥。

根据真实架构选择：

- 模型：候选模型、能力选型、成本、延迟和稳定性；
- Prompt：System Prompt、节点Prompt、输出格式、版本和责任边界；
- 上下文：数据来源、会话历史、用户档案、长度与隐私；
- RAG：知识来源、清洗、分块、召回、重排、引用和更新；
- Agent：任务、输入输出、Workflow、工具、记忆、权限、重试和兜底；
- 评测：核心场景、边缘场景、对抗样本、基准结果、评分标准和上线门槛；
- 线上：成功率、目标达成率、首响延迟、服务可用性、人工标注与用户反馈。

## 通用动态组装规则

不生成固定章节的空壳。根据项目实际情况，从下列问题选择需要回答的部分：

1. 为什么做？
2. 为谁做，在什么场景做？
3. 用户当前怎么解决，哪里有问题？
4. 产品目标和非目标是什么？
5. 这一版做什么，不做什么？
6. 用户、业务、数据和系统如何流转？
7. 每个核心功能的规则、状态和异常是什么？
8. 需要哪些技术、数据、人员和外部依赖？
9. 用什么指标和Case验证？
10. 怎么灰度、上线、监控和回滚？

项目不需要的问题可以不写。
